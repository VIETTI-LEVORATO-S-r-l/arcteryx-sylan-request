# Sylan 2 Collective

Build a premium responsive event application website for:

ARC’TERYX × VIETTI

SYLAN 2 TRAIL RUN

LAKE MAGGIORE

This is NOT a generic event-registration website.

It should feel like a digital extension of a premium Arc’teryx outdoor campaign: technical, minimal, editorial, sophisticated, Swiss-inspired, and highly curated.

--------------------------------------------------

1. PURPOSE OF THE WEBSITE

--------------------------------------------------

The website is for a limited-capacity trail running activation organized by VIETTI in collaboration with Arc’teryx, dedicated to testing the Arc’teryx Sylan 2.

The experience includes:

- welcome at VIETTI

- Sylan 2 fitting

- guided trail run

- experienced run leaders / pacers

- predominantly off-road route

- Lake Maggiore landscape

- post-run refreshments

- community experience

- editorial photo/video storytelling

IMPORTANT:

This is a REQUEST TO PARTICIPATE, not automatic registration.

Users must clearly understand:

“Submitting a request does not guarantee participation.”

Use language such as:

LIMITED SPOTS

REQUEST TO JOIN

PARTICIPATION SUBJECT TO CONFIRMATION

Do NOT use wording that makes every application automatically accepted.

--------------------------------------------------

7. DATE SELECTION SYSTEM

--------------------------------------------------

Create an interactive section:

CHOOSE YOUR PREFERRED DATE

The dates must be configurable from an admin interface/database.

Initial provisional options:

17 SEPTEMBER 2026

18 SEPTEMBER 2026

19 SEPTEMBER 2026

Clearly label them:

PROVISIONAL EVENT DATES

For every date display:

- date

- day of week

- current percentage of participation requests selecting it as preferred

- weather information when available

- voting status

Example:

18 SEPTEMBER

52%

MOST REQUESTED

Each applicant must select ONLY ONE:

PREFERRED DATE

This selection is mandatory.

Also allow separate optional checkboxes:

OTHER DATES I COULD ATTEND

17 SEPTEMBER

18 SEPTEMBER

19 SEPTEMBER

IMPORTANT:

The public percentage must be calculated ONLY from the mandatory “preferred date” selection.

Formula:

number of applications selecting this date as preferred

divided by

total valid applications

× 100

This ensures all displayed percentages total 100%.

Update percentages automatically when a valid application is submitted.

Do not expose participant names, email addresses or personal information.

Only show aggregated statistics.

Highlight the leading date using a subtle Dark Jade glow.

Display:

CURRENT COMMUNITY PREFERENCE

and:

CURRENT LEADING DATE

Do NOT say that the leading date automatically wins.

Use this disclaimer:

“The most requested date will be prioritized. The final event date will be confirmed based on participant availability, weather conditions and operational requirements.”

--------------------------------------------------

8. WEATHER INTEGRATION

--------------------------------------------------

Integrate a reliable weather API for the Lake Maggiore / Arona area.

Make the location and coordinates configurable.

For each proposed date show:

- weather icon

- minimum temperature

- maximum temperature

- precipitation probability

- wind

- weather condition

IMPORTANT:

Do not fabricate forecasts outside the reliable forecast range.

If the date is too far in the future for an actual forecast, show:

FORECAST AVAILABLE CLOSER TO THE EVENT

Do NOT present historical climate data as a weather forecast.

When reliable forecast data becomes available, automatically replace the placeholder with real forecast data.

Add:

LAST UPDATED

[timestamp]

Weather should be informational only.

Do not automatically cancel or confirm an event based solely on weather API data.

10. REQUIRED DECLARATIONS

--------------------------------------------------

Add required checkboxes:

[ ] I understand that this is a trail-running activity taking place on natural and uneven outdoor terrain and requires an appropriate level of physical preparation.

[ ] I confirm that I am physically able to take part in the proposed activity.

[ ] I understand that submitting this request does not guarantee participation and that participation is subject to confirmation by the organizers.

[ ] I have read the Privacy Notice regarding the processing of my personal data for the management of my participation request.

Privacy Notice must open as a separate page or modal.

Do not write fake legal terms.

Create editable legal placeholders clearly marked for final legal review.

--------------------------------------------------

11. MARKETING CONSENT

--------------------------------------------------

Marketing consent must NOT be bundled with event registration.

Create a separate OPTIONAL checkbox:

[ ] I would like to receive news and marketing communications from VIETTI.

Do not pre-select it.

Create an additional configurable optional Arc’teryx marketing consent only if legally required and later approved.

Do not make marketing consent mandatory for participation.

--------------------------------------------------

12. PHOTO / VIDEO INFORMATION

--------------------------------------------------

Include a visible notice:

Photography and video production will take place during the event as part of the Arc’teryx × VIETTI event storytelling.

Do NOT make the first application form contain an overly broad irreversible image-rights waiver.

Instead build a second step for CONFIRMED PARTICIPANTS where the organizers can provide the final image/video release terms.

Create the architecture for this second confirmation step.

--------------------------------------------------

13. TWO-STAGE PARTICIPATION FLOW

--------------------------------------------------

Create these statuses in the database:

APPLICATION_RECEIVED

WAITLISTED

ACCEPTED

DECLINED

CONFIRMED

CANCELLED

First stage:

user submits REQUEST TO JOIN.

Second stage:

organizer reviews applications.

If accepted, user receives a unique confirmation link.

The second participant-confirmation form can collect:

- final attendance confirmation

- emergency contact

- final shoe size confirmation

- event rules acknowledgment

- image/video release

- any legally required event documentation

- optional medical certification information ONLY if later determined legally necessary

Do not publicly expose any of these details.

18. CAPACITY

--------------------------------------------------

Create an editable capacity setting.

Do NOT hardcode 50 participants.

The capacity must be configurable.

When applications exceed capacity:

do NOT close automatically unless the organizer chooses to.

Instead allow:

APPLICATIONS OPEN

WAITLIST MODE

Possible message:

“Applications have exceeded the initial event capacity. New requests may be placed on the waiting list.”

--------------------------------------------------

19. PRIVACY & SECURITY

--------------------------------------------------

Build with GDPR-conscious principles:

- collect only necessary data

- no public personal-data exposure

- encrypted HTTPS connections

- secure database rules

- server-side validation

- input validation

- anti-spam protection

- rate limiting if possible

- no marketing checkbox preselected

- store consent timestamp and privacy-policy version

- provide placeholders for data-controller details

- provide deletion/contact request information

Create editable pages:

PRIVACY NOTICE

EVENT TERMS

COOKIE POLICY

Label the legal text as:

DRAFT — REQUIRES LEGAL REVIEW

Do not invent definitive legal claims.

--------------------------------------------------

20. RESPONSIVE EXPERIENCE

--------------------------------------------------

Prioritize mobile.

The majority of users will arrive from Instagram Stories, Reels and QR codes.

The mobile experience must feel extremely polished.

Use:

- smooth subtle transitions

- light parallax where appropriate

- micro-interactions

- understated Dark Jade glow

- subtle animated topographic lines

Avoid heavy animations.

Performance must remain fast.
